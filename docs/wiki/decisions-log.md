## v0.38.1 / BA-23 — price each round on its own usage (2026-08-23)
- **Gap:** Loop's per-round cost call fed `resolveRoundCost` the stale `lastUsage` carry-over instead of `result.usage`, so a genuinely no-usage round laundered into `costUsd:0`/`'priced'` instead of honest null, and mid-run no-usage rounds billed on the previous round's stale tokens. (prd.md:814-820)
- **Fix:** pass `result.usage ?? null` at the single Loop call site; `lastUsage` itself untouched. PATCH, bugfix only. Cross-repo validated by adopter bareloop (F6 pricing-red halt reachable again). (prd.md:821-826)
- **Known follow-up, deliberately NOT fixed here:** a present-but-empty/malformed usage object (`{}`) still prices as $0 — distinct case needing separate logic (a cache-only round legitimately has `inputTokens:0`), tracked for later (became BA-24). (prd.md:827-829)

## v0.38.0 / BA-21 follow-up — rateSource splits tier vs ceiling (2026-08-23)
- **Flag:** two-value `rateSource:'caller'|'default'` couldn't separate "matched a recognized Claude tier" from "fell back to the blind ceiling." Peer recorded it as an accepted limit; hamr chose to fix anyway. (prd.md:833-836)
- **Decision:** split the guesstimate — recognized haiku/sonnet → `'tier'`; unrecognized/absent → `'default'`. Full set `'provider'|'caller'|'tier'|'default'|null`. Behavior-preserving otherwise (both still warn once-per-instance, both still increment `estimatedRounds`). MINOR bump (new value in public field). Applies to Loop's `onLlmResult` and `judge()`. (prd.md:837-843)
- The companion flag (rateSource dropped at bareloop's own metering callbacks) is bareloop-side, not a bareagent change. (prd.md:844-846)
- **BA-22 (same release):** native (`ownsCycle`) CLIPipe's session-close event stamps `rateSource:'provider'` when its `costUsd` is finite (the CLI's own `total_cost_usd`), `null` when unknown; per-turn event stays `rateSource:null`. A fidelity gap fix, not a bug. (prd.md:847-855)

## v0.37.0 / BA-21 — pricing honesty (2026-08-23)
- **Gap:** cost estimation forced `unpriced` on a null/unknown model, and its fallback priced against an Opus-tier ceiling, over-reporting cheap (Sonnet) models by up to ~33×. (prd.md:859-861)
- **Decision (hamr sign-off):** always price a token-bearing round off an honest guesstimate; default to Sonnet tier ($0.003/$0.015 per 1K), not Opus. Resolution order: caller `rates` → recognized Claude tier (haiku/sonnet substring) → Sonnet-tier default. Hand-curated `COST_PER_1K` table + `_default` key removed (also kills the unguarded dynamic-key lookup). (prd.md:862-867)
- Honesty signalled two ways: structured `rateSource:'caller'|'default'` on every metering payload, plus a loud one-per-Loop-instance `console.warn` on first default-priced round (silenced by passing `rates`). MINOR bump — new `Loop({rates})` option + `rateSource` field. (prd.md:868-875)

## v0.36.0 / decisive return-time judge + calibration harness (bareloop BA-20) (2026-08-12)
> Numbering note: this is bareloop's BA-20, not a bareagent-internal number; first filed as `BJ-1` proposing a new *barejudge* package, re-aimed same day on hamr's ruling ("no new lib for one primitive"). (prd.md:877-883)
- **Where it lands is settled by law:** bareguard's Axis-B detector never calls an LLM (annotates only), so the judge call is caller-side by law, in bare-agent. No bareguard change requested — its two contributions (E6i spec + shipped `gate.annotate` sink 0.7.0) were already delivered. (prd.md:885-891)
- **Sink-shape correction** (reconciled with bareguard maintainer): shipped `gate.annotate` sink is `{surface, verdict, where, meta}`, NOT the pre-E6 sketch `{kind, field, stated, returned, text}` (never shipped; `kind` killed by E6e). The judge doesn't call the sink — a consumer maps the verdict. `where` is a string (bare-agent's `JudgeWhere` object is rendered to one line + field/stated/returned under `meta`); caps: verdict ≤80 chars, where ≤300 (silent clip), meta ≤1000 bytes (all-or-nothing). (prd.md:892-900)
- **Guarantee-scope narrowing:** the adapter's "facts survive the ceiling" guarantee holds for the drained fact + humanChannel event only, NOT the persisted audit row under a configured redactor (redaction runs downstream and expands matches, can still blow the atomic-append cap and be replaced wholesale — measured: a 355-byte legal meta persisted as `{_truncated:true,bytes:6977}`). Two other audit-side loss modes: unserializable meta → `{_unserializable:true}` (distinct marker); audit `where` clip DOES carry a marker (only the source clip was silent). `judgeToAnnotation` returns a single object, never an array, so bareguard's array fail-open can't bite it. (prd.md:901-914)
- **POC-first proved the riskiest assumption:** E6i was measured via CLIPipe→local CLI (subscription); bare-agent ships on its own HTTP `AnthropicProvider`. Ported `judgeDecisive` verbatim, reproduced on claude-haiku-4-5: clear-case 7/7, €280 honored 5/5, injection resisted 5/5, negative control 2/7. (prd.md:915-920)
- **E6i is the design of record**, ported verbatim not redesigned — decisive binary with floor tiebreak, verbatim-request anchor, answer-as-data kept exactly; rejected alternatives (confidence scale, `kind` classification, deterministic carve-out) stay rejected. Only enrichment: mechanical `where` `{field, stated, returned, evidence}`, re-validated live to leave the verdict axis at 7/7. (prd.md:921-927)
- **Calibration harness is half the deliverable:** a tier is admitted only after grading the frozen E6i battery against a pre-registered floor with zero reds; `constantHonored` negative control MUST fail. Truncation/parse-error excluded from graded denominators; cost is honest null. Shipped as `src/judge-calibration.js`. (prd.md:928-932)
- **Disconfirming evidence carried:** injection resistance established at haiku-4.5 ONLY (unresolved on weaker tiers). Judge is drift-conditional (E6c: 0/3 drift under a hard cap), not a general safety layer. (prd.md:933-936)
- **Self-audit found and fixed 3 real gaps pre-release:** (1) per-call `model`/`effort` were dead knobs, removed; (2) `costUsd` was letting `_default` fallback fabricate a price for an unknown tier — now prices only in-table models else null; (3) single injection case expanded to a 5-style battery run as a separate admission gate. Items validated as NOT-defects: token headroom, mechanical-`where` stability across shapes, verdict-axis A/B Δ=0 at N=8, E6b sprawl clause. (prd.md:937-948)
- Consumed by bareloop by version bump (N4's `judged` close stage, `offer:false` by law); no shim, no new production dependency. (prd.md:949-950)

## v0.35.0 / provider total-duration deadline (bareloop BA-19) (2026-07-28)
> Numbering note: bareloop's BA-19, cross-repo ask numbers can collide. (prd.md:952-955)
- **Gap real (unlike BA-18 part 2):** BA-18's `timeoutMs` bounds socket inactivity (`req.setTimeout`, resets on activity) so a "zombie stream" trickling forever is invisible to it — an adopter saw a `generate()` run 274 min, ending in `ECONNRESET` not a `TimeoutError`. Confirmed in source before building. (prd.md:957-963)
- **Opt-in `deadlineMs`, DISABLED by default** (per the ask, contrasting BA-18's finite default) — an absolute non-resetting wall-clock ceiling (`setTimeout`+`req.destroy`, unref'd, cleared on close). A deliberately long single call is legitimate, so this is a knob not a new default. `0`/`Infinity` disable; per-call overridable. (prd.md:964-971)
- **Disable-edge is fail-LOUD:** unset resolves to disabled, but an explicit garbage value (`NaN`) throws `ValidationError` — the deadline has no safe default to fall back to, so silent disable would reintroduce the hang. Both bounds wire through one `applyRequestBounds` seam per `_request`. (prd.md:972-978)
- **Terminal, distinguishable from idle** (user decision: `retryable:false`): on trip, `code:'EDEADLINE'`, `context.bound:'deadline'`, `retryable:false` — a deadline is meant to STOP, not auto-retry (would re-spend up to another full `deadlineMs`). Idle trip carries `context.bound:'idle'` for the same uniform field. With `timeoutMs < deadlineMs`, idle trips first. (prd.md:979-987)
- Same BA-4/5/6/13/17/18 under-modeled-boundary family; filed n=1, a defense-in-depth knob not load-bearing for the adopter. (prd.md:988-994)

(prd.md:1001-1010)

## v0.33.1 / CLIPipe native turn-unit fix (bareloop BA-17) (2026-07-22)
> Numbering note: bareloop's BA-17, criterion-4 follow-up to BA-16. (prd.md:1030-1033)
- **A native turn is one assistant MESSAGE, not one stream event.** The claude CLI emits a separate `assistant` event per content block, each repeating that message's `usage` — counting events inflated turns 5–7× and tokens 5.04×. Fix: a run of consecutive events sharing `message.id` is ONE turn (adjacent-run dedup, no id ⇒ degrade to per-event). (prd.md:1037-1046)
- **The filed ask was measured WRONG about the cause** — `--max-turns` DOES enforce and DOES count assistant turns (both claims false on the wire); the symptom was the event-vs-message mis-count. A cross-repo ask is a symptom report, not a root-cause diagnosis — verify on the real wire first. (prd.md:1047-1054)
- **`maxTurns` enforced TWICE:** the CLI's own `--max-turns` stops cleanly at N; a parent-side counter kills only on overrun (`>` not `>=`, preserving the clean-exit cost report) because the flag is undocumented in `--help`. (prd.md:1055-1062)
- A bounded native session returns its work (BA-5 on native): CLI reports `result:null` on its own bound, so last assistant turn's text carries forward; own-property lookup guards the proto-key. (prd.md:1063-1066)
- Closing session event reconciles the TOKEN axis too: per-turn `usage` is an unrevised first-block snapshot, so the closing event carries the per-tier residual (floored at 0) so a wired gate's tokens sum to the CLI's own total. No new public surface — a patch. (prd.md:1067-1076)

## v0.33.0 / CLIPipe native MCP tool mode (bareloop BA-16) (2026-07-21)
> Numbering note: bareloop's BA-16, consumed by version bump. (prd.md:1079-1081)
- **Native (`toolProtocol:'claude-mcp'`) is the default for the claude CLI; v0.32.0 envelope emulation is RETAINED**, still right for a CLI with no MCP channel. Choice is COST, measured ($0.25–0.55/round emulation vs ~$0.006/turn native), not capability — output-quality parity deliberately UNMINTED (n=2). (prd.md:1084-1091)
- **A cycle-owning provider is a first-class contract (`Provider.ownsCycle`):** the CLI owns the inner turn loop, so the Loop's per-round machinery can't run; governance moves to the `tools/call` bridge — same `policy` chokepoint, BA-11/BA-12 guards, `--max-turns` bound. Any incompatible Loop option (`assemble`/`trim`/`cacheMessages`, Loop-level `policy`) THROWS at construction. (prd.md:1092-1098)
- **Honest accounting is load-bearing:** `GenerateResult.session` + `metrics.sessionTurns` report the real turn/tool count. A dead bridge still ends `subtype:'success'`, so bridge health is tracked parent-side (attempted-vs-served tool calls) and error-tags `bridge-failed` — the CLI's subtype is NOT a sufficient success signal. (prd.md:1099-1104)
- Transport is a unix socket (0600 in a 0700 dir), never a listening port; the fence is set by the mode, not the caller. Claude-only for now. (prd.md:1105-1108)

## v0.29.0 / `shell_edit` — anchored edit verb (bareloop BA-13) (2026-07-15)
> Numbering note: this is bareloop's BA-13, a DIFFERENT item from bare-agent's own BA-13 (termination classifier) — the two numbering schemes diverged at 13. Referred to as `shell_edit` to avoid collision. (prd.md:1112-1117)
- **Gap:** `shell_write` is whole-file — a one-line edit forces emitting the entire file as tool-call JSON (output-token tax ∝ file size), and the maximal broken-tree surface on truncation. (prd.md:1119-1124)
- **Verb:** `shell_edit({path, oldText, newText})` — anchored exact-once replace; `oldText` must occur exactly once. (prd.md:1125-1126)
- **Decisions at sign-off (hamr, 2026-07-15):** anchor miss (0 or 2+ matches) → a refusal returned AS THE TOOL RESULT, not a throw (does NOT feed `maxIdenticalToolErrors`, bounded only by maxTurns/budget); BA-4 param guards THROW on missing/empty `oldText` or missing/non-string `newText` (explicit `newText:''` is legal deletion); atomic (sibling temp+rename, mode preserved); literal splice (index+slice, not `String.replace`, so `$&`/`$1` land verbatim); gated by `{type:'edit'}` — bareguard's `FS_TYPES` already includes `edit`, zero bareguard change needed (source-verified first). (prd.md:1127-1148)
- **Verification:** 11 mutation-checked offline tests + a live economy measurement — 187 vs 31,402 output tokens on claude-sonnet-5, 167.9× cheaper. (prd.md:1149-1157)

## v0.28.0 / BA-13 — honest termination classifier (2026-07-15)
- **One table-driven classifier replaces BA-6's lone truncation short-circuit.** `refusal`, `context_exceeded`, `pause_turn` still fell through into clean empty successes (a benign-prompt-reachable `RECITATION` refusal could score a safety-refused sub-task as CONVERGED up a `recurse` tree). Decision: `classifyStopReason` (`src/provider-stop-reason.js`) over the neutral vocabulary with an explicit pass-through default (next new stop reason degrades to status quo). `refusal→error:'refusal'`, `context_exceeded→error:'context_exceeded'` (both preserve partial text, refuse the round's tool calls); `max_tokens` unchanged. (prd.md:1161-1176)
- **`pause_turn` RESUMES, does not error:** the loop APPENDS the paused assistant turn (partial text + server-tool blocks via `providerBlocks`) then re-requests — the documented Anthropic protocol. A bare `continue` would re-send identical input and spin to `HARD_ROUND_LIMIT`; no new counter added (existing round/maxTurns bound covers it). (prd.md:1177-1184)
- **Error-tag, not merely surface:** `stopReason` is surfaced on every return, but classified terminals are error-tagged because `error` is the sole success signal and `recurse`/bareloop both branch on it — zero `recurse` changes needed. `error:null→'refusal'` is a deliberate BEHAVIOR CHANGE. Bare tags (`'refusal'` not `'refusal:<subreason>'`) for the first cut. Both table lookups use `hasOwnProperty` guards against a proto-key stop_reason. (prd.md:1185-1197)
- Origin: a self-audit of the BA-4/5/6/7 optimistic-rounding class; deterministic probes kept as living regression tests. (prd.md:1198-1200)

## v0.27.0 / Provider fidelity & honest termination — BA-1/4/5/6/7/12 (2026-07-14)
- **Governing finding:** these are protocol/representation-fidelity fixes; at least one (BA-7) carries NO measured capability benefit — shipped labeled honestly, not re-sold as a capability win. (prd.md:1204-1212)
- **BA-6 — truncation is honest:** an output-cap-truncated round returns `error:'truncated:max_tokens'` with partial text instead of laundering to `error:null`; its tool calls are REFUSED, never executed (closes BA-4's file-zeroing root cause at the protocol layer). (prd.md:1213-1218)
- **BA-4/BA-5 — no silent data loss:** `shell_write` REJECTS missing/null/non-string `content`; every terminating path preserves the last non-empty assistant text; `error` stays the sole success signal; `stop()` returns `error:null`. (prd.md:1219-1224)
- **BA-1 — Anthropic transcript stops being re-bought every round:** opt-in `cacheMessages` puts a rolling `cache_control` breakpoint on the last content block of the last message; measured $0.0753→$0.0110/round (6.8×). Ships opt-in for one minor, flips default-ON only after own measurement; must live in the provider; a destructive `trim` rewriting the prefix invalidates it. (prd.md:1225-1233)
- **BA-12 — repeated tool ERROR spins unbounded** (error-side mirror of BA-11 deny guard): `maxIdenticalToolErrors` (default 3) short-circuits on N byte-identical repeats (`name`+`JSON.stringify(args)`) → `error:'stuck:<tool>'`. Narrowest detection by decision — counting ANY consecutive tool error would red the negative controls (varying-args recovery, alternating tools). Counts both the execute-throw and unknown-tool branch via one shared `recordToolFailure`. (prd.md:1234-1241)
- **BA-7 — thinking blocks preserved, not dropped:** new opaque `providerBlocks` carries blocks the normalized shape can't express; replayed at the FRONT of the assistant turn on tool-use continuation. Three constraints: opaque (never re-serialize), provider+model tag enforced on replay (mismatch ⇒ drop, never a 400), normalized content stays source of truth. Adaptive thinking already default on sonnet-5/Opus 4.7+, so the opt-in `thinking` param pins the mode, doesn't enable it. (prd.md:1242-1252)
- **Signed off (hamr, 2026-07-14):** D1 keep `max_tokens` default 4096 but make truncation loud; D2 identical-repeated-call detection; D3 `cacheMessages` opt-in → default-ON later; D4 build order BA-6→BA-1→BA-12→BA-7. Non-goals: making the agent debug better, a retry-on-truncation policy, interpreting `raw` blocks in the Loop. (prd.md:1253-1261)

## v0.16.1 / cost accounting survives provider wrapping (2026-06-15)
- **The response's model wins over the provider's model for cost estimation.** `CircuitBreaker.wrapProvider` returned a bare `{generate}`, dropping `.model`, silently zeroing `budget.maxCostUsd`. Narrow fix: wrapper preserves passthrough props (`{...provider, generate}`). Broader decision: Loop resolves model as `result.model || provider.model || null` — providers now echo `model` in their `generate()` result; `GenerateResult.model?` is additive/optional. Keeps `onLlmResult` cost correct through any wrapping/fallback composition. (prd.md:1300-1318)
- **Security pass (3 grounded findings):** (a) MCP cwd-config trust flipped — `./.mcp.json` no longer trusted by default, `includeProjectConfig` opt-in (behavior change, justified: auto-running cwd code is the wrong default polarity for a library); (b) `shell_grep` ReDoS bounded by worker-thread isolation + hard timeout, not heuristics (the static guard was provably incomplete); (c) `defer` queue fold uses a `Map`+string-id check so a tampered `"__proto__"` id can't reach the prototype setter. (prd.md:1320-1335)

## v0.16.0 / agent-family resilience + routing primitives (2026-06-15)
- **Spawn gets a heartbeat (`idleTimeoutMs`) distinct from the wall-clock ceiling.** Detects "alive but stuck, no output"; arms at spawn, resets on every stdout/stderr line, kills only on genuine silence (SIGTERM→5s→SIGKILL). Defaults off (byte-identical when unset); keeps `timeoutMs` as absolute ceiling. In-loop path needs nothing equivalent (`Retry`'s per-attempt timeout already covers it). (prd.md:1339-1350)
- **Complexity assessment is a pure-code pre-planner, NOT a litectx/CE concern and NOT an LLM call.** `assessComplexity` (4-tier: simple/medium/complex/critical) is a routing question, ported from Aurora's SOAR keyword assessor (~89% vs ~95% full version, accepted tradeoff). Standalone pure function, deliberately not wired into Loop/Planner. Assessed text length-capped after a `.*` quadratic-blowup security finding (~28s→~3ms). (prd.md:1351-1363)

## v0.13.1 / MCP-bridge + provider hardening pass (2026-06-13)
- **A broken MCP stdin pipe must never crash the host.** `child.stdin` had no `'error'` listener, so `EPIPE` became an uncaught exception killing the whole host. Fix: `createRpcClient` attaches a stdin error handler + every write guarded on `child.stdin.writable`. Regression test forces a real fd-level pipe break (not just `stream.destroy()`, which leaves fd 0 open). (prd.md:1367-1378)
- **Every MCP RPC is time-bounded, not just `initialize`.** Moved out of a bespoke `Promise.race` into the RPC layer: `rpc(method, params, timeoutMs)` with one `settle()` clearing the timer on every path. Handshake uses `opts.timeout` (15s default); tool calls use new `opts.callTimeout` (120s default, 0 disables). Also closed a latent unhandled-rejection on the old `Promise.race`. (prd.md:1379-1390)
- **Unvetted MCP server spawns are surfaced, not silenced.** Fail-open default (trust all when no `confirmServer` hook) unchanged — matches IDE behavior — but `createMCPBridge` emits a one-time warning naming every command before spawning, including before the discovery spawn (first thing to execute the command on a cold run). (prd.md:1391-1400)
- **OpenAI provider warns on plaintext-HTTP key transport.** Warns once per instance when the key would go over plaintext http to a non-loopback host; loopback stays silent (legitimate keyless-local case); warns rather than strips the header so local proxies keep working. (prd.md:1401-1408)
- **`examples/wake.sh` validates record ids before pathing on them** — rejects anything not matching the `defer` tool's `def_<base36>_<hex>` id shape, defense-in-depth for a hand-edited queue line. (prd.md:1409-1415)

## v0.10.3 / hardening pass (2026-05-18)
- **Halt is a sealed exit, not a thrown exception.** `HaltError` bubbles out of `wireGate.policy`, but Loop catches it and returns `{error:'halt:<rule>', msgs}` even when `throwOnError:true` — halts are governance decisions, not runtime failures. Adopters wanting exception-shape re-throw from `onError`. (prd.md:1419-1427)
- **Halt-path `msgs` must be a valid OpenAI transcript.** Appends a synthetic `{role:'tool', content:'[halted:<rule>]'}` for every uncovered `tool_call_id` on a mid-round halt, sealing a dangling-tool-calls protocol violation. Lowercase `[halted:]` keeps the v0.10.0 contract that `[HALT:]` never reaches the LLM. (prd.md:1428-1436)
- **`bin/cli.js` fails closed on gate-wiring errors** — `process.exit(1)` instead of running with `policy=null`, since a silently ungoverned child can run any tool (incl. spawn/defer) with zero audit record. Loud failure wins over silent fallback. (prd.md:1437-1444)
- **`bin/cli.js` rewired to the BA1 seam** (`policy+onLlmResult+onToolResult+filterTools`) — the deprecated `wrapTools` path silently dropped LLM cost from `budget.maxCostUsd` and failed to thread `_ctx` into `gate.record`. No adopter config change. (prd.md:1445-1451)
- **`safeStringify` for `onToolResult` results** — raw `JSON.stringify` threw on circular structures / silently emitted `undefined` for functions, falsely surfacing as a gate error rather than a tool serialization quirk. Falls back to `String(value)`. Same fix mirrored in the deprecated `wrapTool` path. (prd.md:1452-1458)
- **`HaltError` public surface is `err.rule`/`err.decision`, not `err.context.rule`/`err.context.decision`** — old duplicates dropped; documented as a searchable break. (prd.md:1459-1464)
- **`COST_PER_1K` is hand-curated and adopter-extensible, not derived** — no model-registry service or auto-fetch pricing; unknown models flow through `_default`, adopters edit the table if budget accuracy matters for a novel model. (prd.md:1465-1471)
- **`filterTools` is bulk-only; MCP inner names gated via `tools.denyArgPatterns`** — documented asymmetry rather than fixed: MCP inner tool names aren't in the bareagent tool list when exposed via `[mcp_discover, mcp_invoke]`, so bulk filtering can't drop them; closing it would mean a per-invocation `gate.allows` cost for an ergonomic feature. (prd.md:1472-1483)

## v0.9 / bareguard 0.2 decisions (2026-04-30)
- Defer/spawn rate caps live in bareguard, counted from the audit log over a trailing 60s window — no bareagent-side counter file. (prd.md:1487-1489)
- Rate caps are per-family (root run_id), not per-process, via the existing `parent_run_id` chain — otherwise a fork-bomb-shaped agent's children evade the parent's count. (prd.md:1490-1493)
- Action shapes are args-wrapped uniformly: `{type, args, _ctx}` for every tool. (prd.md:1494-1497)
- Defer is two phases, two `gate.check` calls, two distinct actions (emit-time vs fire-time via wake.sh), no coupling beyond the shared `parent_run_id`. (prd.md:1498-1501)
- Spawn has two surfaces: LLM-blocking tool form (LLMs can't manage handles across calls) and library `Agent.spawn` handle for advanced use — one underlying primitive. (prd.md:1502-1504)
- Children emit one JSONL channel: stdout = JSONL events; child stderr re-emitted as `{type:'child:stderr'}` events on stdout. (prd.md:1505-1507)
- Defer queue is cwd-only by default (`./bareagent-defers.jsonl`) — project-scoped queue + wake script, one cron entry per project. (prd.md:1508-1510)
- MCP factory + LLM-tools coexist: `createMCPBridge()` returns `{tools, metaTools, ...}` — bulk array for small catalogs, `[mcp_discover, mcp_invoke]` for large ones. (prd.md:1511-1514)
- MCP cache invalidation: TTL only, 30 days default; force refresh via `mcp_discover({refresh:true})`. (prd.md:1515-1516)

## v0.8 / bareguard 0.1.x decisions
- Cronjobs do not belong in bareagent — external schedule = OS cron; long-running watcher = a separate daemon; agent-emitted deferral = `defer` tool emitting JSONL for an external scheduler. (prd.md:1520-1522)
- `barejob` is not built yet — reference `wake.sh` covers 80% of the need; earns existence only after felt pain across 2+ projects. (prd.md:1523-1525)
- No multi-agent framework abstractions — no `class Orchestrator`/`Specialist`/`Crew`; roles are configs, not types; `spawn` is the only primitive. (prd.md:1526-1528)
- Orchestrator pattern lives in `examples/`, not core — reference, not framework. (prd.md:1529-1530)
- All policy moves to bareguard — bareagent has no `if allowed:` checks; every action traverses one gate. (prd.md:1531-1532)
- MCP governance is invocation-level, not catalog-level — bareguard glob-matches tool name strings on invocation only; the catalog lives in bareagent's 30-day cache. (prd.md:1533-1535)
- `mcp_discover` is ungated — discovery is read-only catalog access; only invocations (`mcp_invoke`) are gated. (prd.md:1536-1538)
- Tool name convention `mcp:server/tool` — a string convention for glob-matching; bareguard does no MCP-specific parsing. (prd.md:1539-1540)
- Pre-filter is an ergonomic, not a governance mechanism — `mcp.preFilter:true` uses `gate.allows()` only to omit denied tools from what the LLM sees; gov decisions still happen at invoke time. (prd.md:1541-1544)
- No CodeMode in v1 — trades fine-grained mediation for context efficiency, the wrong trade for a runtime-policy-first stack (the gate would only see the code block). If MCP discovery context bloat becomes real pain, the bare-shaped fix is lazy `mcp_describe(name)`, not CodeMode. Parked. (prd.md:1545-1550)
- Shared budget across siblings is bareguard's problem — backed by a file with `proper-lockfile`; parent passes `BAREGUARD_BUDGET_FILE` via env. (prd.md:1551-1553)
- Communication between agents is JSONL on stdio — no bus, no broker, no shared state beyond the audit log and explicit files. (prd.md:1554-1556)
- The two `tools` keys are intentional, not a naming bug — `agent.tools` is a code registry, `gate.tools` is gov rules. (prd.md:1557-1558)
