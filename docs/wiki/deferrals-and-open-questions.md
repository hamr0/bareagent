## §11.1 Deferred-item validation POCs — empirical ruling (2026-06-28)

Each of the three deferrals above was pitted against what already exists via a real, able-to-fail POC on real wire, triangulated across two methods × two model tiers (claude-haiku-4-5 strong; gpt-4o-mini weak SLM target). POCs kept at `poc/rlm-defer*.mjs` so any can be re-opened. Provenance: #1 RC-4←`/prose`; #2 history-compaction←the RLM paper; #3 calibration←Aurora 2/4/6 + AG-News `window=8` (RLM_PRD.md:954-965).

**#1 — RC-4 capability-matched dispatch → RULED OUT (decisive).**
What we have: every worker gets the same toolset, model picks (SkillRegistry reveals on demand). RC-4 would add: a router offering each sub-task only its matching tool. `rlm-defer1-capability-match.mjs` (16 confusable arithmetic sub-tasks, toolset 1→8→16→24): 100% accuracy / 0 wrong-tool at every size, both models — matched vs all-tools = 0pp. `rlm-defer1b-heterogeneous-tools.mjs` (10 overlapping-description tools, weak model): all-tools 16/16 = matched 16/16. **Un-defer only on a concrete heterogeneous-worker case that demonstrably misroutes** (larger/messier toolset or weaker-than-gpt-4o-mini model). Family-A already has the *pull* analogue (`skill_use`) shipped (RLM_PRD.md:967-981).

**#2 — History-compaction (`fit(history)`) → NOT cleanly ruled out; overflow REAL & REPRODUCIBLE on the weak SLM target.**
What we have: copy-on-return + handles keep heavy data out of window; no active compaction. Honest bar = small-model window (8k/4k), not 200k. Strong model (haiku) fan-out width 3→6→9: 1445→2200→3113 tok, clean linear growth, never near 4k — **ruled out on strong model**. Iterative axis (both models), 5→10→20 sequential calls: 710→1368→2688 tok at 20 steps, well under budget — **ruled out**. Weak model (gpt-4o-mini) fan-out: node window REPRODUCIBLY overflowed 8k across 4 runs (peaks 8098/9632/3745/18982 tok, 3 of 4 crossed); peak tracks CALL COUNT not requested width (43 calls→3745 ok; 117 calls→18982) — the weak model over-decomposes, and the transcript blows the window; a ×3 repeat falsified an earlier "one-off" dismissal (RLM_PRD.md:983-1001).
Ruling — deferral is now a CHOICE, not a non-issue, with two caveats: (1) POCs ran UNGOVERNED — with bareguard wired, call/budget/depth caps trip FIRST, turning the runaway into honest `{incomplete}` (governance is first-line, not `fit(history)`); (2) `fit(history)`'s real value is graceful continuation vs today's halt-incomplete — the root cause is over-decomposition, better targeted by a weak-model depth/width discipline (`maxDepth=1`, tighter spawn prompt). Un-defer condition effectively MET on the weak tier for "graceful continuation on small models"; tracked as a real follow-on, not closed. Recommended order: (a) confirm bareguard bounds it → (b) weak-model spawn discipline → (c) `fit(history)` (RLM_PRD.md:1002-1012).
Caveat (a) **PROVEN** — `poc/rlm-defer2c-governed-bound.mjs` (live gpt-4o-mini, 2026-06-29): a real Gate (`budget.maxCostUsd $0.01` + `limits.maxTurns 8`) over the same 43–117-call over-decomposition: 3/3 governed runs halted at 4–5 calls, peak window ~545–738 tok (never near 8k), cost ~$0.011, clean `{incomplete}` — no uncaught throw, no faked pass. **History-compaction deferral is SAFE as documented**: governance is a real first-line bound; `fit(history)` remains an optional graceful-continuation enhancement, never a correctness need (RLM_PRD.md:1013-1023).

**#3 — Calibration (auto-tune scan `window`) → RULED OUT (triangulated; no knee reproducible).**
What we have: fixed `window=8` (AG-News-calibrated). Auto-calibration would add value ONLY if the knee is data-dependent (would flip the deferral). `rlm-defer3-calibration-sweep.mjs` (short~7w vs long~52w, window 4/8/16): recall 1.00 everywhere — too easy, inconclusive. `rlm-defer3b-calibration-hard.mjs` (harder: 5 confusable categories, short~11w vs long~82w, window 4/8/12/16/24, single pass, both models): recall 1.00 at every window/length/model — even 24×82-word items didn't under-enumerate; no knee formed, window=8 never broke, wider never hurt. **Un-defer only if a real task is found where recall collapses at window=8** (mechanism then = the active half-window probe, not the falsified positional-skew detector). Aggregation stays CODE either way (RLM_PRD.md:1025-1041).

## §11.2 Pre-publish residual ledger — the honest "not all clean" list (2026-06-28)

Recorded after a self-audit pushed back on an "all clean" ship claim for the RLM build (steps 1–8); code logic sound, but genuine residuals existed (RLM_PRD.md:1043-1051).

**Open by design (risk acknowledged, not a bug).** Cost/burst is OPEN — no intrinsic total-work cap on the Family-A default: an ungoverned `recurse` can spawn up to a Loop's `HARD_ROUND_LIMIT`(100) children/level × `maxDepth`; bounded only by the gate. Run with bareguard (or any token/USD cap); `maxDepth:1` is the local brake without a gate. Forced `fanout`/`partition` ARE bounded (deterministic count + concurrency cap + pre-wave checkpoint); only the model-driven default is open. The brake half of the stance is PROVEN (not just warned): `poc/rlm-defer2c-governed-bound.mjs` cuts the 43–117-call ungoverned runaway to 4–5 calls, clean `{incomplete}`, on the live weak model (RLM_PRD.md:1053-1065).

**Tracked follow-on (real, unresolved — see §11.1 #2).** History-compaction is NOT closed: node-window overflow reproduces on the weak SLM tier (up to 18982 tok across an 8k budget). Governance caps trip first → honest `{incomplete}` (shipped behavior), so this is a graceful-continuation enhancement, not a correctness hole, but a genuine open follow-on. Order: confirm bareguard bounds it → weak-model spawn discipline → `fit(history)` (RLM_PRD.md:1067-1074).
